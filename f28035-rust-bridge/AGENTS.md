# 项目维护规则

适用于本仓库内的后续修改。开始工作前阅读 `README.md`、相关路线文档和最近的
`WORK_LOG.md` 记录。

当前工作重心（2026-10-21）：除非用户明确要求，后续任务只推进 PATH B-1。
PATH A、MIR、应用迁移及其测试失败不纳入 B-1 的修复范围，也不作为 B-1
构建、发布或完成判定的阻塞项。

1. 每次修改代码、脚本、配置、测试或工程文档时，同步更新相关路线文档：
   - 应用、Safe HAL、MIR、硬件 case、安全与迁移：`docs/path-a/PATH_A.md`
     （同目录的 `F28035_RUST_DEV_GUIDE.md` 是开发与接手指南）。
   - LLVM、ABI、工具链、B-1：`docs/PATH_B.md`；旧 B-2 仅在同级归档目录保存。
   - 同时涉及两条路线时，两份都更新。把新结论写进当前说明，避免只在旧资料章节后追加互相矛盾的说法。
2. 每次修改都在相关路线文档开头的“维护记录”加一行，写日期、改动主题和结论。
3. 每次修改都在 `WORK_LOG.md` 增加一条记录，写清楚：改了什么、为什么改、
   过程中发生了什么、运行了哪些验证及结果、尚未解决什么。失败、回退、
   未运行的测试和需要外部硬件的步骤也要如实记录。
4. 记录状态只依据实际证据。硬件 case 的状态以各 `case.toml` 为准；
   不把构建成功记作上板通过，不把计划写成已经完成。
5. 不重写或删除以前的日志条目；纠错时新增一条说明。路线总文档保持两份：
   PATH A 文档集在 `docs/path-a/`（`PATH_A.md` + `F28035_RUST_DEV_GUIDE.md`），
   PATH B 在 `docs/PATH_B.md`。两套互不引用：PATH A 目录内不出现 B 路线文档
   链接，PATH B 不复制 PATH A 的台账数字；需要交叉信息时由 `README.md` 做入口。
   不再拆出重复的专题文档。

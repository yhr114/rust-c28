# 2026-09-30 source repair batch

Status: source edits and regression inputs only. The compiler has NOT been
rebuilt and the regression cases have NOT been executed as part of this batch.
Do not interpret this document as a target execution pass.

## Changes

- CMP32 now ends in SUBL, clobbers ACC/ST0, preserves XT, and has no stack
  adjustment. Both operands are used as specified by the instruction.
- ADD32 handles either input in ACC and restores ACC only for an XT result.
- Register copies distinguish ACC, XT, their halves, and XAR registers.
  Truncation reads the correct low half; zero-extension reaches the actual
  destination. XAR subregisters are queried through the register description.
- MOVL_XAR_AR retains its internal name but emits MOVZ, including correct ARn
  assembly spelling. It no longer copies an arbitrary source high half.
- Indirect calls use XAR7 as an input and retain implicit argument uses and
  register masks. ACC arguments are restored before the call.
- Global addresses relocate the bare TI word symbol, convert it to a logical
  byte pointer, and then add the byte offset. Odd offsets are not rounded.
  Unexpected residual symbol offsets are rejected instead of misencoded.
- MC lowering drops implicit registers and register masks from encoded
  operands. PUSH/POP ACC explicitly describe SP, ACC and memory effects.
- Ordinary and frame-based 16-bit loads/stores preserve unrelated live ACC
  contents when using the accumulator as scratch.

## Deferred validation

1. Back up and sync the edited backend using tools/sync-and-build-c28x.ps1
   when compiler building is resumed. This script also builds; do not run it
   just to inspect these changes.
2. Build llc and FileCheck, then run the RUN commands in repair-20260930.mir
   and repair-20260930.ll. Also run tools/verify-llvm-c28x.ps1. Review any
   changed byte oracle against TI encoding before updating expected bytes.
3. Add an object-byte check for MOVZ AR0,AR1: 58A1 (bytes A1 58), followed by
   LRETR: 0006. Confirm high bits of XAR0 become zero on target.
4. Rebuild/relink the patched rustc against this backend before the Cargo
   smoke test. An old rustc passing does not validate the new backend.
5. Execute the oracles in the .ll file on a simulator or the board; repeat
   with optimisation disabled and enabled. These are logical-byte pointers,
   not interchangeable with TI C pointer values.
